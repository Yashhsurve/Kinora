This document provides a comprehensive line-by-line and section-by-section audit
of the original mini project report against the actual codebase of Kinora
(package.json, server.js, services/mediaData.js, public/app.js, public/index.html,
public/styles.css, README.md, and .env.example).

CRITICAL ACADEMIC FRAMING CONTRADICTION IN ORIGINAL REPORT:
The assigned college mini project topic for the Artificial Intelligence subject is:
"A Rule-Based Recommendation System (movie/series suggestion)".
The original report completely failed to recognize this topic. Instead, it fabricated
fictitious machine learning training, high-dimensional neural embeddings, and academic
semiotics, while completely omitting the real, production-ready rule-based recommendation
engine implemented in the code.

The corrected report accurately re-frames Kinora as a HYBRID AI RECOMMENDATION SYSTEM:
a deterministic, knowledge-based Rule-Based Recommendation Engine combined with a
Generative AI (Google Gemini LLM) conversational reasoning and grounding layer. Every
statement below documents where the original report deviated from the real codebase,
citing specific files, functions, and code lines.

4. CHAPTER 2: WORKING PROCEDURE (Pages 5 to 7)
--------------------------------------------------------------------------------

[4.1] Complete Omission of the Rule-Based Recommendation Engine
- Original Text: Completely omitted any mention of mood-to-genre ontologies, candidate
  pool harvesting, IF-THEN filters, regional threshold adaptations, Bayesian weighted
  scoring, franchise deduplication, or discovery styles.
- Why it is wrong (services/mediaData.js lines 816-1213):
  The core assigned AI topic of the project is a rule-based recommendation system! Over
  400 lines of services/mediaData.js are dedicated to this exact engine:
  - `MOOD_CONFIG` table mapping 8 moods (Cozy, Hyped, Heartbroken, Mind-bending, Scared,
    Nostalgic, Laugh-out-loud, Inspired) to specific TMDB genre IDs and keywords.
  - IF-THEN rules for runtime clamping (under 90 min, under 2 hrs), media types, and
    temporal cutoffs (Nostalgic <= 2005).
  - Regional language threshold rules: vote count v >= 1500 for global English, but
    relaxed to v >= 300 for regional Indian/international cinema (Hindi, Tamil, Telugu,
    Korean, etc.) with rating R >= 6.8.
  - Graceful fallback relaxation rules if qualified candidates < 15 (v >= 800/150, R >= 6.5).
  - Bayesian Weighted Rating: WR = (v/(v+m))*R + (m/(v+m))*C.
  - Composite Scoring: Score = 0.5*normPop + 0.3*normWR + 0.2*moodGenreFit.
  - Franchise and sequel deduplication (`filterSequelsAndDuplicates`) using regex to retain
    only the earliest entry in a franchise.
  - Discovery styles: Popular, Hidden Gems (v between 300-2500, R >= 7.5), and Balanced Mix.
- Corrected Text: Section 2.1 now provides an exhaustive mathematical and algorithmic
  breakdown of the rule-based engine, including a complete mood mapping table, formal IF-THEN
  rules, the exact Bayesian scoring formulas, and a step-by-step worked numerical example
  calculating the score and badge for "Shutter Island".

[4.2] False Claim of Custom Machine Learning Model Training & Neural Embeddings
- Original Text: Suggested that recommendations were produced via deep learning embeddings,
  latent vector clustering, or trained neural network models.
- Why it is wrong (package.json, services/mediaData.js):
  There is NO machine learning training code, NO PyTorch, NO TensorFlow, and NO vector
  database (Pinecone, ChromaDB) in the codebase. Kinora is a HYBRID AI system where
  candidate filtering and ranking are 100% rule-based and deterministic, while conversational
  dialogue and natural language parsing are handled by Gemini LLM. Falsely claiming ML
  model training is academic dishonesty.
- Corrected Text: The report explicitly clarifies what is rule-based and what is LLM-generated,
  verifying that ranking is computed via deterministic Bayesian statistics and content-based
  attribute rules, not black-box neural embeddings.

[4.3] Fabricated Prompt Directives & "Semiotic Perspectives"
- Original Text: "Inject Cultural & Semiotic Prompt Directives... enforcing three critical
  evaluation perspectives: 1. Cross-Cultural Narratology... 2. Structural Semiotics...
  3. Sociopolitical Context... dispatched via @google/genai through gaxios connection pools."
- Why it is wrong (server.js lines 23-34, 229-295):
  The server constructs a system instruction consisting of `KINORA_BASE_PROMPT` (concise
  3 to 6 lines, bold title recommendations with runtime and year), an `honestyRule`
  (never state a title does not exist without tool confirmation), a `lookupRule` (always
  call tools before answering factual queries), active mode instructions, and strict
  `spoilerShieldPrompt` rules. There is zero mention of semiotics or narratology, and
  `gaxios` is not a project dependency.
- Corrected Text: Accurately documents Kinora's prompt engineering: persona definition,
  brevity constraint, Honesty Rule, Lookup Rule, and dynamic watch boundary injection.

[4.4] Protocol Buffer Serialization Claim
- Original Text: "Data buffers are serialized and standardized through protocol buffer
  structures (@protobufjs/) for efficient transfer."
- Why it is wrong (package.json, server.js lines 201-205, 483-507):
  Kinora does not use `@protobufjs/` or protocol buffers. Client-server data streaming
  is implemented entirely using standard HTTP Server-Sent Events (SSE, MIME type:
  `text/event-stream`), where JSON-encoded events are written incrementally to the response
  stream (`res.write('data: ...\n\n')`).
- Corrected Text: Accurately documents real-time Server-Sent Events (SSE) streaming with
  paced 25ms token delivery, Title Inspector event payloads, and premature client close
  handling (`res.on('close')`).

[4.5] Fabricated Comparison Flowchart
- Original Text: "Analyze Feudal Ronin Archetype -> Map to Lone Gunslinger Trope ->
  Examine Structural Mise-en-scene -> Contrast Nihilism with Western Individualism"
- Why it is wrong (server.js lines 151-185, services/mediaData.js lines 1360-1510):
  Kinora's Compare & Debate feature executes a two-stage pipeline:
  Stage 1: Fetches real TMDB and OMDb data in parallel for Title A and Title B (IMDb ratings,
  runtime, genres, streaming providers) to render comparison metrics.
  Stage 2: Gemini evaluates the two titles across structured criteria (Story, Acting,
  Pacing, Rewatch Value, Cultural Impact) and outputs targeted advice ("Watch X if...").
- Corrected Text: Section 2.2 documents the actual two-stage Compare & Debate architecture.

[4.6] Misrepresentation of Spoiler Shield as a Regex Filter
- Original Text: Misrepresented the Spoiler Shield as simple post-generation regex string
  matching or ignored it.
- Why it is wrong (services/mediaData.js lines 635-805, server.js lines 435-470):
  The Spoiler Shield is an upstream data-filtering architecture:
  1. Backend Upstream Filtering: In `executeTool()`, when `get_season_episodes` is called,
     all episodes beyond the user's progress point (> targetEpisode) are completely pruned
     from the database payload. In `get_details`, TV status is clamped and upcoming season
     cast lists are masked. In `search_title`, live Wikipedia scraping is disabled on
     protected titles to prevent uncontrolled web plot leaks.
  2. Grounding Elimination: Because the forbidden plot data NEVER enters Gemini's context
     window, the model is mathematically prevented from hallucinating future twists.
  3. Defense-in-Depth: Prompt boundary guardrails and a zero-temperature Flash-Lite safety
     audit evaluate the generated text before sending to the client.
- Corrected Text: Fully documents the multi-layered upstream data-path filtering, prompt
  guardrails, and zero-temperature safety audit.

[4.7] Misrepresentation of Taste Profile & Watchlist Personalization
- Original Text: Claimed high-dimensional user embedding profiles or cloud-synced databases.
- Why it is wrong (public/app.js lines 21-30, 507-515):
  Kinora does NOT maintain server-side user vectors or cloud accounts:
  1. Taste Profile is implemented as pre-configured UI quick-prompt chips (e.g., "Based
     on my love for Dark and Inception, recommend 3 hidden gems") that pass user genre/title
     constraints directly into Gemini's context window.
  2. Watchlist is a client-side localStorage store (`kinora_watchlist_v1`) that records
     saved titles, status, and dismissed items locally in the user's browser.
- Corrected Text: Section 1.3 and Chapter 2 accurately describe Taste Profile as contextual
  prompt engineering chips and Watchlist as browser localStorage persistence.
